## 1. 对比目前Elfiee

| 维度     | Insights.md        | 当前 Elfiee           |
| ------ | ------------------ | ------------------- |
| 核心用户   | PM、产品负责人、团队 Lead   | 开发者                 |
| 核心场景   | 需求评审 → 决策冲突 → 共识沉淀 | 写代码 → 任务提交 → AI 上下文 |
| 协作性质   | 强多人，团队网络效应         | 弱多人，主要是人+AI         |
| 价值兑现周期 | 慢循环（数周）+ 快循环（即时）   | 即时（每次 commit）       |
| 平台形态   | Web 协作平台（agentour） | 本地编辑器 + MCP         |

本文评估的是**insights 里描述的路径**：Consensus History → What is Good Doc → Traceability（Phase 1），再到 Skill Map + Collaboration Map（Phase 2）。


## 2. Phase 1 功能评估

### 2.1. Consensus History

**用户价值：强，痛点明确**

三个 User Story 指向三类真实痛苦：
- "为什么当初这么设计" → 新成员 onboarding 成本极高
- "我们之前讨论过这个" → 重复争论消耗团队能量
- "当时怎么决定的" → 历史决策的归因与复盘

这个痛点的特殊之处：用户不是"不知道有这个需求"，而是"天天感受到但认为无解"。一旦产品能以极低摩擦捕获决策记录，感知价值会很高。

**最大风险：网络依赖**

Consensus History 的价值依赖于**至少两个人同时使用**。单人使用时，它只是一本自言自语的日记。冷启动故事（个人插件版）是合理的破解思路，但它只解决了"记录"问题，没有解决"引用"问题——一条从未被别人看到的洞察，沉淀了什么？

### 2.2. What is Good Doc

**用户价值：极高，有真正的差异化**

这是整个系统里最有价值、也最独特的部分。它解决了一个组织长期存在的悖论：

> 最佳实践文档要么是无人维护的过时遗产，要么是高层拍脑袋写的理想状态——两者都和实际发生的事情脱节。

WIG Doc 的核心创新是：**原则来自真实决策，不是来自委员会**。"强度"（Strength）机制让知识库具备自净能力——一条原则被 Traceability 证实，强度提升；被证伪，强度下降。这是可防御的差异化。

**一个设计隐患**

快循环例子里，"老板建议"终止了 Challenge，系统提炼出原则 P-094："听老板的是好的沟通方式（成功率 99%）"。

这是一个危险的学习路径。系统可能会系统性地强化**权威服从**模式，而非**最优决策**模式。两者在短期数据上高度相关，但在长期组织健康上是对立的。需要在数据模型层面做区隔，不能只靠 AI 提炼。

### 2.3. Traceability

**用户价值：高，但兑现周期长**

Traceability 是整个系统的地基，让所有上层知识获得可信度背书。快循环（封版即闭环，针对沟通质量）保证了用户在每次封版时就能看到反馈，不需要等待数据——这是留住用户度过等待期的关键机制。慢循环（上线后数据回填，针对业务原则）则验证了沟通的结果是否可靠，即使是在快循环中让双方一拍即合的决策，也需要在慢循环中再次验证其正确性。

**落地难点：实际值的回填**

Traceability 最脆弱的地方是"实际值谁来填"：
- 数据散落在 BI 系统、增长平台、客服系统
- 活动结束后没有人有动力回来填数据
- "预期值"在封版时是否足够精确，本身就是变量

这个问题不解决，慢循环就变成死循环。要么系统自动从数据平台拉数据，要么在需求上线的自然流程节点强制触发。


## 3. Phase 1 → Phase 2 依赖合理性

Skill Map 和 Collaboration Map 依赖 Phase 1 的数据积累，逻辑是对的：

```
Consensus History → 谁在什么话题上提出了 Challenge / Reasoning
What is Good Doc  → 哪些 Challenge 被证实是有价值的
Traceability      → 哪些判断最终是对的
↓
Skill Map         → 每个人在哪些领域判断力强（行为证据，非自评）
Collaboration Map → 谁和谁协作时摩擦大 / 效率高 / 有认知盲区
```

**核心价值在于数据来源**：Skill Map 的数据来自**行为证据**，而非自我申报。"老板的活动形式建议成功率 99%" 这条数据比任何简历上写的都可信。这是真正的护城河。

**时间线是现实风险**

每个人至少需要积累 20-30 个有 Traceability 闭环的决策记录，Skill Map 才有足够置信度。如果每人每月参与 3-4 个需求，需要 6-9 个月才有足够数据。Collaboration Map 需要更长。

产品需要在 Phase 1 阶段靠**快循环价值**（即时的沟通模式洞察）维持用户粘性，等待慢循环数据积累。


## 4. 产品价值判断

> 框架：产品价值 = 用户价值 + 商业价值
> 
> - 用户价值 = 新体验 − 旧体验 − 替换成本
> - 商业价值 = 用户规模 × 客单价 × 付费频次

### 4.1. 用户价值

**旧体验**：决策发生在 Slack / 飞书 / 会议里，消失得无影无踪。PM 每次遇到类似问题，要重新翻聊天记录、找当事人问"当时为什么这么决定"；新成员不知道哪些设计是有意为之、哪些是历史债务；Senior 的判断力看不见，只有头衔。

**新体验**：决策过程自动沉淀，下次遇到类似 challenge 时 WIG Doc 主动弹出历史依据；新成员可以独立理解"为什么"；每个人的判断记录可追溯、可量化。

**替换成本**：这是本产品最需要警惕的地方。用户需要把需求评审行为从 Slack / 会议迁移到系统里，行为改变成本高，是冷启动的最大阻力。个人 PM 插件模式（在原有文档工具中写评论、系统自动捕获）是降低替换成本的正确方向。

**用户价值的五个阶段**

| 阶段 | 在本产品中的表现 |
|------|----------------|
| 生存：满足基本需求，进入备选 | "我能搜到三个月前那次讨论的结论" |
| 安全：超越预期，建立选择理由 | "我的判断有数据验证，不只是我自己说" |
| 社会：扩大用户群，实现破圈 | "我引用了一条有项目证据的 WIG，Frank 也开始用了" |
| 尊重：获得好评与认可 | "我在客诉风险识别上的 Skill Strength 是全团队最高的" |
| 自我：建立品牌心智标签 | "Elfiee 上的决策记录就是我的专业履历" |

冷启动故事指向的是**生存阶段**：PM 不需要改变任何行为，只是写了一条评论，知识就被沉淀了。这是进入备选的最短路径。Skill Map 的数据积累则驱动用户从生存走向尊重和自我——这是长期留存的根基。

### 4.2. ToB 价值

**用户规模**：目标是拥有 10 人以上产品团队的中型互联网公司和企业。部门级切入比企业级采购更现实，Team Lead 是关键的付费决策者。

**客单价**：按席位或按团队订阅。Skill Map 和 Collaboration Map 是 Team Lead / HR 级别的功能，存在自然的向上销售路径：从个人工具升级为团队管理工具，客单价随之跳级。

**付费频次**：月付或年付。年付有利于绑定团队度过数据积累期（慢循环至少需要数月才能体现价值，年付锁定了这个等待期，对产品更有利）。

**ToB 的三个核心价值点**

1. **知识留存**：人员离职导致的隐性成本被严重低估。一个 Senior PM 离职，带走的不只是经验，而是数百条未成文的判断逻辑。WIG Doc 是组织对抗人员流动的保险。
2. **决策加速**：每次需要 30 分钟解释背景的讨论，如果系统能自动引用历史共识，可以压缩到 5 分钟。这是可量化的 ROI，是说服采购的最短链路。
3. **扩张时的标准化**：跨团队、跨地区扩张时，WIG Doc 是保持决策一致性的基础设施，这是企业级客户愿意为之付费的理由。


## 5. 当前市场分析

### 5.1. 竞品格局

| 工具 | 做了什么 | 没有做什么 |
|------|----------|-----------|
| Jira / Linear | 管理任务流转与状态 | 不记录决策逻辑，不追踪业务结果 |
| Notion / Confluence | 存储文档与知识 | 文档静态，不从决策行为中自动提炼，不验证原则有效性 |
| Slack / 飞书 | 记录沟通过程 | 信息碎片化，无法提炼，无法追踪到结果 |
| GitHub | 管理代码变更历史 | 不连接业务 outcome，不适用于产品决策层 |
| Dovetail / Maze | 用户研究沉淀 | 只做研究侧，不覆盖决策全链路 |

### 5.2. 市场空白

没有任何工具在做这条完整链条：

```
决策过程（Challenge / Reasoning）
→ 原则提炼（What is Good Doc）
→ 结果验证（Traceability）
→ 技能量化（Skill Map）
→ 协作优化（Collaboration Map）
```

这是一个**新品类**，而非现有工具的功能补充。新品类的好处是没有直接竞争；坏处是用户教育成本高——需要让用户理解"决策记录本身是有价值的"，而不是功能堆叠。

### 5.3. 切入时机

AI 工具（Claude Code、Cursor、Copilot）的爆发正在重构知识工作者的生产方式，但 AI 目前擅长执行，不擅长决策归因。"AI 做了很多，但为什么这么做、结果是否达预期"的问题没有工具解决。Elfiee 的原始路径恰好填补这个位置：**给 AI 时代的知识团队提供决策的可追溯性**。这是当下有窗口期的切入点。


## 6. 路径成立的两个前提条件

**前提 1：需求评审等的思考和迭代数据要能输入到系统中**

Phase 1 的数据源头是需求评审时的 Challenge / Reasoning。如果这个过程发生在 Slack / 飞书 / 会议中，而不在系统里，所有数据就不存在。数据需要有明确的入口。

**前提 2：Traceability 的实际值能被可靠回填**

慢循环的闭环依赖数据回填，需要设计。
