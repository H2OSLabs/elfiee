## 详细 User Journey

### UJ-TL-001｜浏览 Project 的完整事件时间线

**场景** 用户刚接手一个 Project，希望通过时间线快速了解项目从创建至今的整体演进过程：什么时候创建了哪些 Block、哪些 Task 被执行和提交、哪些 Editor 参与了协作。

**流程**

- 用户在 Project 界面打开「Timeline」面板。
- 系统从 `_eventstore.db` 加载事件流，按时间顺序渲染为可视化时间线。
- 时间线上的每个节点代表一个事件，以图标或颜色区分事件类型（创建、修改、删除、授权等）。
- 用户可滚动浏览，缩放时间范围（日/周/月视图），快速定位到感兴趣的时间段。

**预期结果**

- **全局视角：** 用户在几秒内即可把握 Project 的整体规模和活跃度。
- **类型可辨：** 不同类型的事件在视觉上有清晰区分，无需逐条阅读。
- **时间导航：** 用户可自由在时间维度上移动，不局限于"最近的事件"。

### UJ-TL-002｜按 Block 过滤查看特定文件的演进

**场景** 开发者发现某个代码文件存在问题，需要追溯它的修改历史：何时被创建、被谁修改过、每次修改了什么。

**流程**

- 用户在 Timeline 中选择「按 Block 过滤」，指定目标 Block（通过 VFS 路径或 block_id）。
- 时间线仅展示与该 Block 相关的事件：创建事件、内容修改事件、关系变更事件、权限变更事件。
- 每个事件节点展示操作者和操作摘要。
- 用户可点击任意事件节点查看该次修改的详细内容。

**预期结果**

- **历史聚焦：** 过滤后的时间线仅包含目标 Block 的事件，排除无关噪声。
- **演进可见：** Block 从创建到当前状态的完整变更链条清晰可见。
- **问题定位：** 用户可快速找到"引入问题的那次修改"及其操作者。

### UJ-TL-003｜按 Editor 过滤查看特定操作者的活动

**场景** 项目负责人想要了解某个 AI Agent 在过去一段时间内做了哪些操作，以评估其贡献度和行为质量。

**流程**

- 用户在 Timeline 中选择「按 Editor 过滤」，指定目标 Editor（人类用户或 AI Agent）。
- 时间线仅展示该 Editor 的操作事件。
- 事件按时间顺序排列，展示操作对象（哪个 Block）、操作类型（哪种 Capability）、变更摘要。
- 用户可进一步按 Capability 类型二次过滤（如只看 `markdown.write` 或 `core.grant`）。

**预期结果**

- **操作者聚焦：** 清晰展示单个 Editor 的所有活动，不掺杂其他操作者的事件。
- **行为画像：** 通过事件分布，用户可判断该 Editor 的工作模式（集中还是分散、偏重编辑还是权限管理）。
- **多维下钻：** 支持在 Editor 过滤基础上再按 Capability 细分，实现逐层聚焦。

### UJ-TL-004｜跳转到特定事件点查看当时状态

**场景** 用户在浏览时间线时发现一个关键事件（如某次大规模修改），希望查看该事件发生后 Project 的完整状态快照，以理解当时的上下文。

**流程**

- 用户在 Timeline 中选中目标事件节点，选择「查看此刻状态」。
- 系统通过 State Projector 从事件流的起点回放到目标事件，重建该时刻的完整状态。
- 用户可以查看该时刻的 Block 内容、VFS 结构、权限表等信息。
- 用户可在历史状态与当前状态之间切换对比。

**预期结果**

- **时间定点：** 用户可以"回到过去"查看任意事件发生后的完整 Project 状态。
- **上下文还原：** 不仅看到"改了什么"，还能看到"改的时候项目是什么样的"。
- **对比能力：** 历史状态与当前状态的对比帮助用户理解变更的累积影响。

### UJ-TL-005｜查看 Task 级别的完整演进视图

**场景** PM 想要回顾某个 Task 从定义到归档的完整生命周期：需求是如何演化的、谁参与了执行、过程中发生了哪些关键决策、最终成果如何。

**流程**

- 用户选择目标 Task，打开其「Task Timeline」视图。
- 系统聚合与该 Task 直接或间接关联的所有事件：
  - Task Block 自身的创建与修改事件。
  - 通过 `implement` 关系关联的 Block 的变更事件。
  - 与 Task 绑定的 Session 事件（Agent 对话记录）。
  - Task 状态变更事件（Pending -> InProgress -> Committed -> Archived）。
- 时间线按阶段分段展示，每个阶段（定义、执行、提交、归档）有视觉分隔。

**预期结果**

- **全链可见：** Task 的完整生命周期在一条时间线上完整呈现。
- **阶段分明：** 不同阶段的事件在视觉上有清晰划分，帮助用户快速定位。
- **因果清晰：** 用户可看到"因为做了 A，所以发生了 B"的因果链条。
