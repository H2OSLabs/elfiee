

> **格式约定：** 本文档描述 Task Block 的完整 User Journey，覆盖从“意图被显式捕获”到“进入可提交、可归档闭环”的全过程。
> 不描述 API，不讨论实现细节，仅描述 **用户视角 + 系统行为 + 状态变化**。

---

## 1. Task 的产品定义

在 Elfiee 中，Task 包含一次明确意图（Intent），会作为后续 Commit / Archive / Skill Evolution 的唯一入口

---

## 2. Task 生命周期总览

Task 具有一个**强约束的状态机**：

```
Pending → InProgress → Committed → Archived
```

- **Pending**：意图已存在，但尚未进入执行
- **InProgress**：已有实现行为与之产生因果关系
- **Committed**：意图对应的实现已被外部世界确认
- **Archived**：该意图已转化为可复用、可学习的经验对象

## 4. 详细 User Journey

### UJ-TASK-01｜创建 Task（Intent Capture）

**场景** 用户产生了一个初步想法或目标，需要在系统中将其“实体化”以供后续追踪和执行。

**场景流程**

- 用户在 GUI 中点击创建 Task，或 AI 在外部对话中识别到需要建立新任务的指令。
    
- 系统创建一个 `block_type = task` 的 Block。
    
- 系统将 Task 的初始状态设为 `Pending`。
    
- 系统为该 Task 分配全局唯一标识，使其成为一个可被后续行为引用的节点。
    

**预期结果**

- **意图对象化：** 模糊的自然语言转化为一个结构化的“对象”。
    
- 用户明确感知到：_“我要解决的问题已被系统记录，即便它目前还不完整。”_
    

---

### UJ-TASK-02｜写入与演化 Task 内容

**场景** 随着讨论的深入或研究的开展，原始任务的背景和目标需要被细化和修正。

**场景流程**

- 用户或 AI 助理对 Task 的描述、背景、约束、目标等字段进行增量修改。
    
- 系统将每一次修改动作记录为独立的 Event（事件）。
    
- 系统保留 Task 的版本演化轨迹，支持历史回溯。
    

**预期结果**

- **意图渐进明细：** Task 允许“意图逐步清晰”，不强求一次性定义准确。
    
- 最终形成包含背景、约束、目标和风险的完整意图描述。
    

---

### UJ-TASK-03｜Task 与执行行为建立关系

**场景** 当真正的开发或创作行为发生时，将其与目标任务挂钩，确立“为什么而做”。

**场景流程**

- AI 或人类创建代码、文档、配置等具体的 Block 实体。
    
- 执行者显式声明或系统推断：_“该行为是为了完成 Task [X]”_。
    
- 系统在 Task 与该执行 Block 之间建立因果关系（如 `implement` 关系）。
    
- 系统将 Task 状态自动更新为 `InProgress`。
    

**预期结果**

- **因果锁定：** Task 进化为**执行网络的上游节点**。
    
- 用户无需手动维护清单，系统自动关联行为与目标。
    

---

### UJ-TASK-04｜Task 作为因果锚点被持续引用

**场景** 在复杂的长周期协作中，所有相关的修改、讨论和测试都围绕该任务聚合。

**场景流程**

- 后续产生的 Event、Session 或子 Block 持续引用该 Task。
    
- 系统将所有关联行为聚合在 Task 的因果图（Causal Graph）中。
    
- 系统提供反查功能，支持从 Task 视角追溯所有相关的原始执行记录。
    

**预期结果**

- **上下文锚点：** Task 成为协作的“共识中心”，为新加入的 AI 或成员提供即时上下文。
    
- 在 AI 推理时，Task 作为高质量的 **Context Anchor**，有效过滤无关噪音。
    

---

### UJ-TASK-05｜Task 进入可提交状态

**场景** 当任务的阶段性目标达成，准备将其成果交付或合并到主工程中。

**场景流程**

- 下游关联的实现逻辑（Blocks）已达到预期完整度。
    
- 用户或 AI 发出“任务可提交”的确认指令。
    
- 系统校验 Task 的关联关系是否闭合（即：是否所有预定目标都有对应的实现）。
    
- 系统将 Task 标记为逻辑上的 `Committable` 状态。
    

**预期结果**

- **闭环验证：** Task 从“执行中的意图”转变为“可被验证的因果假设”。
    
- 标志着该任务已准备好接受外部世界的验证或合并。
