## 1. Session Ingestion 的产品定义

在 Elfiee 中，Ingestion 包括：

- 对外部 AI 行为的筛选
- 对原始推理轨迹的时间序写入

---

## 2. Session Ingestion 在整体闭环中的位置

```
External AI Tool
   (Claude / Cursor)
        │
        │  Session Files
        ▼
Session Discovery
        │
        ▼
Session Ingestion  ←── 事实写入闸门
        │
        ▼
Events / Evidence / Linking
        │
        ▼
Task / Commit / Archive / Skill
```

Ingestion 的质量，直接决定：
- AI 行为是否“看得见”
- 失败路径是否会被保留
- 学习是否建立在完整历史之上

## 4. 详细 User Journey

### UJ-INGEST-01｜启动 Session 监听（进入感知状态）

**场景** 当项目环境就绪后，系统自动开启后台监听任务，准备捕获 AI 的实时产出。

**场景流程**

- 系统检测到 Project 已打开且 Session Discovery 成功锁定目标。
    
- 系统确认 Agent 处于 `Enabled` 状态。
    
- 系统为每个已发现的 Session 初始化独立的写入缓冲区（Buffer）。
    
- 系统挂载监听句柄，进入“可增量读取”的活跃状态。
    

**预期结果**

- **静默监听：** 监听过程默认开启，用户无需点击“录制”，也不会收到任何干扰提示。
    
- 系统底层已建立稳定的实时数据流入通道。
    

---

### UJ-INGEST-02｜增量读取 Session 内容

**场景** 用户在外部工具（如 Cursor 或本地 Agent）中与 AI 交互产生新内容时，系统进行同步。

**场景流程**

- 外部 Session 文件或接口检测到内容增量（如新的推理路径或 Tool Call）。
    
- 系统仅提取相对于上次读取位置的新增字节/字符。
    
- 系统按照原始发生的时间顺序进行流式读取。
    
- 系统保持内容的原始性，不进行任何自动总结或脱水处理。
    

**预期结果**

- **忠实记录：** 记录的是“发生过什么”的完整现场，而非经过过滤的“重要部分”。
    
- 同步过程对外部工具的性能和用户体验零影响。
    

---

### UJ-INGEST-03｜写入 Session 事实记录

**场景** 读取到的原始数据被持久化到系统的底层存储中。

**场景流程**

- 系统接收到增量内容，将其转化为系统内部的“事实记录”。
    
- 系统为记录打上元数据标签：来源工具标识、绝对时间戳、原始上下文引用。
    
- 记录被存储在 Project 下的 Session 历史库中，此时不与任何具体的 Task 进行自动绑定。
    

**预期结果**

- **事实层构建：** 生成一套未经人为或算法解释的、纯净的原始事实数据。
    
- 为后续的 AI 审计、回溯和 Block 转化提供最可靠的底层证据。
    

---

### UJ-INGEST-04｜处理中断与恢复

**场景** 在遇到应用关闭、系统重启或外部工具崩溃等意外情况时，确保数据不丢失。

**场景流程**

- 系统在每次成功读取后实时更新并保存“读取进度位点”（Checkpoint）。
    
- 当系统重启或恢复连接后，自动对比 Checkpoint 与外部文件当前状态。
    
- 系统从断点位置继续读取，补齐中断期间产生的增量数据。
    

**预期结果**

- **数据连续性：** Session 历史在时间维度上保持完整，无重复、无遗漏。
    
- 用户无需手动干预“重新导入”，系统具备自我修复能力。
    

---

### UJ-INGEST-05｜停止或切换 Ingestion

**场景** 当用户改变工作重心（切换项目或禁用 Agent）时，系统自动调整监听目标。

**场景流程**

- 用户触发 Project 切换或将 Agent 设为 `Disabled`。
    
- 系统立即挂起当前活跃的监听进程。
    
- 系统封存当前的进度位点，并释放相关的系统资源。
    
- 根据新 Project 的语境，重新初始化新的监听任务。
    

**预期结果**

- **上下文隔离：** 监听行为始终与当前 Project 语境严格对齐。
    
- 系统资源得到有效利用，不会在非活跃项目上消耗性能。
