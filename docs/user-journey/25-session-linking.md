## 4   详细 User Journey

  
### UJ-SESSLINK-01｜生成候选关联（因果提示）

**场景** 当系统捕捉到新的 AI 行为或用户创建了新任务时，系统尝试在幕后寻找它们之间的潜在联系。

**场景流程**

- 系统检测到新 Session 写入或新 Task 被创建。
    
- 系统基于多种信号计算关联概率：
    
    - **时间接近度：** 行为与任务是否发生在同一时段。
        
    - **语境重合度：** 活跃 Task 的描述与 Session 内容的文本相关性。
        
    - **显式引用：** Session 中是否提到了 Task 的 ID 或关键词。
        
- 系统在界面上以“建议”形式提示用户，而非直接修改数据结构。
    

**预期结果**

- **智能辅助：** 用户不需要手动翻找聊天记录，系统主动提出：“这些行为，可能和某个 Task 有关”。
    
- **主权在人：** 系统仅提出因果主张，不擅自做最终裁决。
    

---

### UJ-SESSLINK-02｜确认 Session 与 Task 的关联

**场景** 用户或 AI 助理对系统提出的建议进行审阅，并正式建立业务联系。

**场景流程**

- 用户查看候选建议并点击确认，或在执行过程中通过指令显式声明引用。
    
- 系统接收并记录这一明确的“因果主张”。
    
- 系统将原本孤立的 Session 事实正式标记为该 Task 的执行证据。
    

**预期结果**

- **显式授权：** 因果关系的成立必须经过确认，确保系统逻辑的严谨性。
    
- 用户表达出明确的判断：“这些行为，是在解决这个问题”。
    

---

### UJ-SESSLINK-03｜写入因果链接（结构化历史）

**场景** 关联确认后，系统在底层数据库中织入一条结构化的因果链条。

**场景流程**

- 系统在后台建立 `Session ↔ Task / Block` 的持久化链接。
    
- 系统同步记录关联元数据：谁关联的（人/Agent）、关联发生的时机、关联的权重或类型。
    
- 系统确保护链条的透明度，允许后期被回溯或质疑。
    

**预期结果**

- **事实转证据：** Session 从一份“孤立事实”转变为一份“有归属的因果证据”。
    
- 用户能感知到上下文已被自动聚合，形成了有条理的历史线。
    

---

### UJ-SESSLINK-04｜更新 Task 视图与上下文完整性

**场景** 关联成功后，Task 的信息密度增加，成为一个包含决策过程的丰满实体。

**场景流程**

- Task 视图自动刷新，聚合展示关联的 Session 内容。
    
- 系统将这些关联的 Session 纳入该 Task 的“活跃上下文池”。
    
- 后续的 AI 推理或 Agent 执行可直接引用这些已关联的历史背景。
    

**预期结果**

- **决策现场还原：** 用户在 Task 中能直观看到相关的讨论、关键尝试及被否定的路径。
    
- Task 不再只是一个标题，而是逐步变成了“真实发生过的决策现场”。
    

---

### UJ-SESSLINK-05｜修正或否定既有关联

**场景** 随着项目推进，用户发现之前的关联存在偏差，需要进行校准。

**场景流程**

- 用户在关联视图中选择解除或调整某个 Session 的归属。
    
- 系统断开该因果链接，并更新 Task 的上下文范围。
    
- 系统严格保留原始 Session 事实，仅修正其指向的 Task 映射。
    

**预期结果**

- **可校准性：** 历史可以被修正，但发生过的事实不被抹除。
    
- 保证了系统的容错率，防止错误的关联误导后续的 AI 决策。
