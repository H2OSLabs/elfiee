## 1. Task Archive 的产品定义

在 Elfiee 中，Archive 是对已验证 Task 的资产化处理

---

## 2. Task Archive 在整体闭环中的位置

```
Task (Intent)
 ↓
Execution (AI / Human)
 ↓
Evidence (Terminal / Tests / Logs)
 ↓
Commit  ← 因果确认点
 ↓
Archive ← 经验固化点
 ↓
Skill Evolution / Reference
```

如果没有 Archive：
- Commit 只是一次历史事实
- AI 无法区分“偶然成功”和“可复用路径”

## 4. 详细 User Journey

### UJ-ARCH-01｜发起 Task Archive（经验评估请求）

**场景** 当任务对应的代码或成果已提交并稳定后，用户或系统发起评估，决定如何将其转化为长期记忆。

**场景流程**

- 用户明确点击“归档任务”，或系统在检测到 Commit 成功且运行稳定后自动弹出归档提示。
    
- 系统启动 Task Archive 事务流。
    
- 系统维持 Task 的 `Committed` 状态，直至经验评估与资产化过程完成。
    

**预期结果**

- **价值判断化：** 归档不再是行政动作（Cleanup），而是一次价值判断请求。
    
- 用户表达的是一种反思：_“这次尝试，是否值得被未来参考？”_
    

---

### UJ-ARCH-02｜汇聚 Task 的完整因果链

**场景** 系统在后台自动“剪辑”该任务从诞生到终结的完整纪录片。

**场景流程**

- 系统扫描并聚合与该 Task 关联的所有关键要素：
    
    - 初始意图描述及演化历史（Task Blocks）。
        
    - AI 推理过程与工具调用记录（Sessions）。
        
    - 最终形成的物理产出（Implement Blocks）。
        
    - 外部验证证据（Git Commits）。
        
- 系统将这些碎片自动化整为零，形成一条连贯的、具备逻辑因果的时间线。
    

**预期结果**

- **无感复盘：** 用户无需手动写总结，系统自动提取“为什么这样做会成功/失败”的逻辑链条。
    
- 形成的“因果原材料”不仅包含结果，更包含决策路径。
    

---

### UJ-ARCH-03｜区分成功归档与失败归档

**场景** 系统对汇聚的因果链进行定性，将其分类为不同性质的经验资产。

**场景流程**

- 系统基于 Commit 状态、测试结果或人工反馈进行判定：
    
    - **成功归档：** 标记为“正向经验”，作为未来类似任务的推荐范式。
        
    - **失败归档：** 标记为“负样本资产”，记录哪些路径是行不通的。
        
- 系统在归档元数据中明确标注失败的原因（如：技术方案不匹配、环境冲突等）。
    

**预期结果**

- **负样本资产化：** 失败经验不再是噪音，而是极具价值的避坑指南。
    
- 系统能清晰理解：哪些是“要学习的”，哪些是“要规避的”。
    

---

### UJ-ARCH-04｜生成归档资产对象

**场景** 将庞杂的执行过程压缩为一个紧凑、可引用的“经验单元”。

**场景流程**

- 系统生成一个类型为 `archive_block` 的独立对象。
    
- 系统对 Task 信息进行“有损压缩”：保留核心逻辑与因果锚点，隐藏冗余的中间过程，但保留指向原始数据的深层引用。
    
- 建立 Archive Block 与原 Task 及其产出物的双向关联。
    

**预期结果**

- **经验单元化：** 执行过程被封装成“可被 AI 再次调用的知识块”。
    
- 用户看到的是一个清晰的、代表“一段历史”的资产对象。
    

---

### UJ-ARCH-05｜更新 Task 状态并退出执行循环

**场景** 任务正式退出当前的活跃工作区，进入历史仓库。

**场景流程**

- 系统确认 Archive Block 创建成功。
    
- 系统将 Task 状态更新为 `Archived`。
    
- 系统将该 Task 从活跃执行队列（Active Context）中移出，使其不再参与即时执行操作。
    

**预期结果**

- **状态终结：** Task 从“执行对象”正式转变为“历史样本”。
    
- 标志着一个因果闭环的彻底完成，系统资源与注意力被释放至新任务。
    

---

## 阐述理由 (Explain Rationale)

- **负样本的战略价值 (Value of Negative Samples)：** UJ-ARCH-03 强调了失败归档。对于 Agent 而言，知道“什么行不通”和知道“什么行得通”同等重要。在基于历史经验的推理中，失败归档能显著降低 Agent 重复犯错的概率。
    
- **信息密度管理 (Cognitive Load Management)：** UJ-ARCH-04 采用“压缩”逻辑。如果直接把所有原始 Session 丢进未来任务的 Context 中，会造成严重的噪音干扰。通过生成 Archive Block，我们为 AI 提供了**高密度的知识摘要**。
    
- **因果闭环原则 (Closure Principle)：** 整个 Archive 流程是 agentour “学习型系统”特征的体现。通过将执行（Task）转为知识（Archive），系统实现了自我的迭代演进。
