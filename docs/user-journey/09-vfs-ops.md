## VFS Operations 

在理解了 VFS 的硬链接语义后（路径是 dentry，Block 是实体），本文档聚焦于 **dentry 上的具体操作**。

## 详细 User Journey

### UJ-VFSOP-01｜在目录中新建文件/文件夹条目

**场景**
用户在 Project 的目录树中需要新建一个文件或文件夹。新建文件意味着同时创建一个 dentry 和一个新 Block；新建文件夹仅创建一个目录节点。

**流程**

- 用户在目标目录下触发"新建文件"或"新建文件夹"操作。
- 若新建文件：系统创建一个新 Block（分配 `block_id`），并在目标目录下创建指向该 Block 的 dentry。
- 若新建文件夹：系统创建一个目录类型的 Block（或纯组织节点），其 `children` 关系用于容纳子条目。
- 用户为新条目命名，名称成为 dentry 的路径段。
- 新建操作产生对应的 Event（Block 创建 + dentry 创建）。

**预期结果**

- **原子操作**：新建文件是一次原子操作——Block 创建与 dentry 绑定同时完成。
- **即时可见**：新条目立即出现在目录树中，可被点击进入编辑。
- **事件完整**：Block 的创建和 dentry 的建立均被记录为独立的 Event，可在 Timeline 中追溯。

---

### UJ-VFSOP-02｜重命名目录或文件条目

**场景**
用户发现某个文件或文件夹的名称不再合适（如拼写错误、需求变更），需要重命名。在 Elfiee 中，重命名只改变 dentry 的路径字符串，Block 的 `block_id`、内容和所有关联关系均不受影响。

**流程**

- 用户在目录视图中选中条目，触发"重命名"操作。
- 用户输入新名称，系统验证新路径在当前目录下不冲突。
- 系统更新 dentry 的路径段，产生一条 dentry 变更 Event。
- 若该 Block 被其他 dentry 引用，其他路径不受本次重命名影响。
- Block 本身的 `block_id`、`contents`、`children` 等属性完全不变。

**预期结果**

- **Block 不动**：重命名是纯路径层面的操作，Block 的任何属性均不受影响。
- **关联安全**：该 Block 与 Task 之间的 `implement` 关系、与其他 Block 之间的引用关系均不会断裂。
- **历史连续**：Block 的 Timeline 不因重命名而产生断点——因为 Event 的 Entity 是 `block_id`，不是路径。

### UJ-VFSOP-03｜移动条目到其他目录

**场景**
用户需要重构 Project 的目录结构——将文件从一个目录移动到另一个目录。这是最能体现 dentry 语义价值的操作：移动改变的是路径，不是 Block。

**流程**

- 用户通过拖拽或右键菜单将条目从源目录移动到目标目录。
- 系统将 dentry 的父级从源目录变更为目标目录，路径段保持不变（除非目标目录下有同名冲突）。
- Block 的 `block_id` 不变，`contents` 不变，所有 `children` 关系不变。
- 该 Block 与 Task、Evidence 等的关联关系完全不受影响。
- 移动操作产生一条 dentry 变更 Event。

**预期结果**

- **零副作用**：移动文件不会触发任何 Block 级别的变更，不会产生 Block Event。
- **引用不断**：所有通过 `block_id` 建立的关系（Task 关联、Block 间引用）均保持完整。
- **可批量执行**：移动操作的轻量性使得批量目录重构成为低风险操作。

---

### UJ-VFSOP-04｜删除目录或文件条目

**场景**
用户从目录中移除一个不再需要的条目。此操作移除的是 dentry（路径绑定），而非 Block 本身。如果该 Block 在其他目录下仍有引用，它将继续存在。

**流程**

- 用户在目录视图中选中条目，触发"删除"操作。
- 系统提示用户确认：此操作将移除路径引用。若该 Block 仅有此一个 dentry，系统额外警告"此为该 Block 的最后一个路径引用"。
- 确认后，系统移除该 dentry，产生一条 dentry 移除 Event。
- 若删除的是文件夹，其下所有子 dentry 递归移除。
- 失去所有 dentry 的 Block 成为孤儿，进入 GC 候选队列（不立即销毁）。

**预期结果**

- **渐进式安全**：系统对"最后一个引用"给出额外警告，防止用户无意中使 Block 成为孤儿。
- **递归语义**：删除文件夹会递归处理子条目，但每个 Block 的存亡取决于其是否还有其他 dentry。
- **可恢复**：即使 Block 成为孤儿，在 GC 执行前仍可通过 `block_id` 恢复引用。

---

### UJ-VFSOP-05｜批量重构目录结构

**场景**
Project 发展到一定阶段后，用户需要对目录结构进行大规模重组——调整层级、合并目录、重新分类文件。在传统文件系统中这是高风险操作，但在 Elfiee 的 dentry 语义下，这只是路径映射的批量变更。

**流程**

- 用户选中多个条目或整个目录子树，执行批量移动或重命名。
- 系统逐一处理每个 dentry 的路径变更，每个变更产生独立的 Event。
- 所有涉及的 Block 均不受影响——`block_id`、`contents`、`children`、Task 关联等完全不变。
- 重构完成后，用户在新的目录结构下看到所有内容完整可用。
- 若重构过程中发生错误（如路径冲突），系统可回滚到重构前的状态。

**预期结果**

- **低风险重构**：批量目录变更不涉及 Block 数据，大幅降低重构的风险与心理负担。
- **原子回滚**：由于每步操作都产生 Event，出错时可精确回滚到任意中间状态。
- **历史完整**：重构前后，每个 Block 的 Timeline 连续不断——因为 Block 本身没有任何变更。
