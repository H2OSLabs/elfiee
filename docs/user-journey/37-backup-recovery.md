## 详细 User Journey

### UJ-RECOV-01｜手动/自动创建备份

**场景** 用户需要为重要项目创建备份副本，或系统在关键操作前自动创建备份。

**场景流程**

- **手动备份：** 用户在项目设置或菜单中选择"创建备份"，系统将当前 `.elf` 文件完整复制到用户指定的位置或默认备份目录。

- **自动备份：** 系统在以下关键时机自动创建备份：
    - 项目打开时（保存一份"上次正常打开"的副本）。
    - 执行可能影响大量数据的操作前（如大规模导入、批量删除）。
    - 定时备份（如每小时或每天，频率可配置）。

- 备份文件以时间戳命名（如 `project_2025-01-15T14-30.elf.bak`），存储在配置的备份目录中。

- 系统维护备份轮转策略：保留最近 N 份备份，超出部分自动清理（N 可配置）。

**预期结果**

- **有备无患：** 用户在出现问题前就已经有了可用的备份。自动备份确保即使用户忘记手动备份，也有安全网。

- 备份轮转防止备份文件无限增长占满磁盘。

### UJ-RECOV-02｜从备份恢复完整项目

**场景** 用户的 `.elf` 文件损坏或误操作导致数据丢失，需要从备份恢复。

**场景流程**

- 用户在 Dashboard 或项目设置中选择"从备份恢复"。

- 系统展示可用备份列表：备份时间、文件大小、备份类型（手动/自动）。

- 用户选择一个备份版本，系统执行恢复：
    - 当前（可能损坏的）`.elf` 文件被重命名保留（如 `project.elf.corrupted`），避免覆盖丢失。
    - 选中的备份文件被复制为当前工作文件。

- 系统对恢复后的文件执行完整性校验（参见 UJ-RECOV-04），确认恢复成功。

- 恢复完成后，系统显示恢复报告：恢复到的时间点、备份后丢失的修改数量（如果可以估算）。

**预期结果**

- **安全恢复：** 恢复操作不会销毁当前文件（即使已损坏），用户始终有"后悔药"。

- 用户能清楚地了解"恢复到了什么时间点"以及"丢失了多少近期修改"，做出知情决策。
